# Real-time audio generators

NyxMap's audio instruments run **in the audio device callback**, independent of the
video frame rate. They are not rendered to a WAV or a fixed-length clip.

In **Media Bin → Audio → Generators**, drag **FM**, **Granular**, **White Noise**,
**Pink Noise**, or **Video Sonification** onto a layer. **Audio → Sounds** lists the sound
files, **Audio → Inputs** the sound inputs of the machine (microphones, sound card
inputs; a dragged input is a live sound with its volume, its Audio FX and its levels).
The bin has two roots, **Video** and **Audio**; the media filter (Video + Audio, Video,
Audio) and the kind filter (Files, Generators, Inputs, ISF) narrow it. Select that layer
and adjust its Source controls while it plays. Each instrument has **attack,
decay, sustain, release and gate** controls. A gate rising from 0 to 1 retriggers
its ADSR; lowering it releases the sound. Pause releases the built-in envelope;
mute, hiding a layer and composition blackout also silence its output.

The control addresses start with `synth/` (for example `synth/frequency`,
`synth/grainMs`, `synth/attack`, `synth/gate`). They use the normal parameter
system: undo, OSC, timelines, snapshots, presets and project save/restore.

## Engines and portability

Instruments use **Faust** from **GRAME**: `os.osc`, `no.noise`, `no.pink_noise`,
`en.adsr` and `ef.transpose`. The latter uses two crossfaded delay lines for grain
pitch shifting, combined with windowed grain pulses in the instrument. The DSP
program is `audio/faust/NyxSynth.dsp`; its C++ generated by Faust **2.79.3** is
included in the source tree. Ordinary builds need no Faust compiler, server,
external process or platform-specific audio plugin. Audio output remains NyxMap's
existing miniaudio backend.

This path uses portable C++ on macOS, Windows and Linux. Verification in the cloud
is on Linux; native macOS/CoreAudio and Windows/device validation remain required.
To regenerate the checked-in C++, install Faust 2.79.3 and run
`scripts/generate_audio_dsp.sh` (`FAUST_LIB_PATH` can select a local library directory).
See `audio-engine-research.md` for the evaluated alternatives and source links.

## FM, noise and granular parameters

Recipe files (`.nyxaudio`, JSON version 1) define initial controls. Editing a recipe
requires reloading it; changing the inspector/OSC controls takes effect while
playing. Example:

```json
{"version":1,"type":"fm","frequency":220,"ratio":2,"index":3,"gain":0.2,
 "attack":0.01,"decay":0.1,"sustain":0.8,"release":0.2,"gate":1}
```

Types are `fm`, `white`, `pink`, `granular` and `video`. Common gain is 0–1.
ADSR times are 0.001–10 s; sustain and gate are 0–1. Frequency is 20–8000 Hz,
FM ratio 0.01–16, depth 0–20. High-index FM is not band-limited and can alias.

```json
{"version":1,"type":"granular","source":"voice.wav","grainMs":80,
 "density":25,"pitch":1,"position":0.5,"gain":0.2}
```

Granular samples are decoded to mono **once when loaded**, limited to their first
60 seconds. The sound itself is synthesized in real time. Without a sample the
input is a Faust sine oscillator. Grain size is 5–500 ms, density 1–100/s, pitch
0.125–8 and sample position 0–1. The delay pitch-shifter introduces a grain-window
latency and uses a bounded 65,536-sample delay; its window is capped at 30,000
samples. This is a streaming granular instrument, not a corpus/mosaic selector.
Its sample cursor is free running; transport speed affects it, but layer seek and
reverse/ping-pong do not reposition or reverse the synthesis state.

`source` is a local path relative to the recipe, or an absolute path. Project
collection does not inspect dependencies inside recipes: copy referenced samples
manually when moving projects. Invalid values and unavailable sources fail visibly.

## Live video sonification

```json
{"version":1,"type":"video","frequency":220,"ratio":2,"index":3,"gain":0.2}
```

Put the video on a visual layer and add a Video Sonification instrument on another layer.
The instrument listens to **one viewport**: in its Source tab, **Watches** chooses which
(the first viewport by default; the composition itself only when the project has no
viewport). It analyses that viewport's output as it goes out, with its own size, opacity
and color space, effects, mixing and live inputs included, so each instrument can follow
a different picture (a screen for the room, another for the stage). The small swatch
next to **Watches** shows the color it sees. A 16×16 GPU tap is averaged every render
tick: brightness controls amplitude, red versus blue shifts pitch, green controls FM
depth. The audio thread smooths this input and continuously synthesizes sound. A video
does not need an audio track. The choice is saved with the layer (`sonification_viewport`);
if that viewport is deleted, the instrument falls back to the first one.

The tap reads each watched viewport once per frame (instruments that watch the same
viewport share the read), not an individual video layer. It performs a small synchronous
GPU readback on the rendering thread; graphics stalls can delay new visual controls, but
do not stop audio callbacks. This is sampled color sonification, not per-pixel spectral
conversion. Black images produce silence.

## User Faust programs: audio equivalent of programmable visual generators

With **libfaust's interpreter compiler** available at build time, import `.dsp`
files through the Media Bin just like other audio sources. CMake detects the
headers, library and standard libraries; use `NYXMAP_FAUST_COMPILER=OFF` to omit
this optional capability. On macOS, `brew install faust` supplies the dependency;
on Debian/Ubuntu use the distribution's `faust` package. Windows builders must
supply matching libfaust headers/library through `CMAKE_PREFIX_PATH` or the
`FAUST_COMPILER_INCLUDE_DIR`, `FAUST_COMPILER_LIBRARY`, `FAUST_LIBRARY_PATH` cache
entries. Missing compiler support reports a clear error for `.dsp` files; all
built-in instruments still work on every platform.

libfaust is loaded locally through its C ABI, with deep symbol binding where supported, to isolate its compiler symbols from graphics drivers. It is not linked into NyxMap at startup. Compilation and DSP initialization happen only when loading. UI widgets are
discovered automatically, exposed in the inspector, and saved at stable numeric
addresses `synth/<label>` (the control's label in lower case: `level`, `cutoff`; `p0`, `p1`… when it has none; `_2` after a repeated one). A program may have 0 inputs (generator), or
4 inputs (sample input, red, green, blue; sample input currently supplies zeros),
and 1 or 2 outputs. Up to 128 scalar controls are supported; soundfile widgets are
rejected. Widget order must stay consistent to restore saved numeric addresses.
A control named `gate` is lowered when paused. Standalone Faust controls do not
automatically get ADSR: include `en.adsr` in the program when wanted.

```faust
import("stdfaust.lib");
f = hslider("Frequency", 220, 20, 2000, 0.1) : si.smoo;
g = hslider("Gain", 0.1, 0, 1, 0.001) : si.smoo;
process = os.osc(f) * g;
```

Bundled app distributors enabling this feature must package libfaust, its license
materials and standard `.lib` files, and configure their runtime search location.
Current portable release packaging does **not** yet register this optional compiler
or relocate the standard-library path; built-in instruments do not depend on it.
